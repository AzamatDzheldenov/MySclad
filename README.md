# 📦 МойСклад — Система управления оптовыми заказами и остатками (HoReCa)

Комплексная система для оптовой компании по дистрибуции расходных материалов (стаканчики, крышки, сиропы, аксессуары). Включает реляционную базу данных PostgreSQL с защитой от **Race Condition**, асинхронный REST API на **FastAPI**, веб-панель менеджеров с **Канбан-доской** и **Telegram-бота** для водителей и кладовщиков на **aiogram 3.x**.

## 🚀 Быстрый запуск на VPS сервере (одной командой)

### 1. Требования
* Сервер с ОС Ubuntu 20.04+ / Debian 11+ / macOS.
* Установленные `docker` и `docker compose`.

### 2. Запуск
Клонируйте репозиторий на сервер, перейдите в папку проекта и выполните:

```bash
cp .env.example .env && docker compose up -d --build
```

После завершения сборки и запуска:
* **Веб-панель менеджеров (CRM):** `http://<IP_СЕРВЕРА>/`
* **Swagger UI (Интерактивная API документация):** `http://<IP_СЕРВЕРА>/docs`
* **Healthcheck:** `curl http://<IP_СЕРВЕРА>/health`

## 💻 Локальный запуск без Docker (для разработки)

```bash
# 1. Создание виртуального окружения
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt

# 2. Накатывание схемы и сидов на локальный PostgreSQL
psql -U postgres -d moysklad -f sql/schema.sql
psql -U postgres -d moysklad -f sql/seed.sql

# 3. Запуск FastAPI сервера
uvicorn app.main:app --reload --host 0.0.0.0 --port 8000

# 4. Запуск Telegram-бота (в отдельном терминале)
export TELEGRAM_BOT_TOKEN="ваш_токен_от_BotFather"
export API_BASE_URL="http://localhost:8000/api"
python3 -m app.bot.telegram_bot
```

Веб-панель менеджеров также можно открыть напрямую в браузере: файл `frontend/index.html` (включает автоматический Demo-режим с товарами и заказами, если бэкенд не запущен).

## 🔒 Защита от Race Condition и Deadlock

### 1. Проблема
Два менеджера одновременно оформляют заказ на последние коробки товара. Если просто делать `SELECT` -> проверка -> `UPDATE`, оба менеджера увидят доступный остаток и подтвердят заказ, уведя склад в минус.

### 2. Решение в проекте
* На уровне БД: жесткие `CHECK`-ограничения (`stock_quantity >= 0`, `reserved_quantity >= 0`, `stock_quantity >= reserved_quantity`).
* На уровне приложения: **пессимистическая блокировка `SELECT ... FOR UPDATE`**.
* **Защита от взаимных блокировок (Deadlocks):** все транзакции всегда сортируют `product_id` по возрастанию (`ORDER BY id ASC`), гарантируя одинаковый порядок блокировки строк в PostgreSQL.
* Если остатка не хватает хотя бы на 1 коробку, транзакция мгновенно откатывается и API возвращает `409 Conflict` со структурированным массивом дефицитных позиций.

### 3. Нагрузочный тест параллельного резервирования
В репозитории есть готовый стресс-тест `tests/test_concurrency.py`, который эмулирует 5 одновременных заказов через `asyncio.gather`:
```bash
python3 tests/test_concurrency.py
```

## 📱 Сценарии работы в Telegram-боте

1. **/start или /login — Авторизация:**
   * Отправка контакта по кнопке «📱 Отправить мой номер телефона» или ввод кода сотрудника (например, `4` — водитель Ерлан, `3` — кладовщик Бауржан).
   * Сохраняет `telegram_chat_id` в базу данных.
2. **Сценарий водителя (/my_orders):**
   * Выводит заказы в статусе «В пути» с адресом, клиентом, суммой и составом.
   * Кнопка **«✅ Доставлен»**:
     1. Выбор оплаты: «Наличными» или «Безналичный расчет».
     2. Бот запрашивает фото подписанной бумажной накладной.
     3. После отправки фото отправляется `POST /api/orders/{id}/delivered`, заказ переводится в `delivered`, а физический остаток (`stock_quantity`) и резерв атомарно списываются.
   * Кнопка **«⚠️ Проблема с заказом»**: передача комментария диспетчеру/менеджеру.
3. **Сценарий кладовщика:**
   * При переводе любого заказа в статус «На сборке» бэкенд шлет push-уведомление кладовщику с составом позиций.
   * Кнопка **«✅ Собрано (Готов к отгрузке)»** переводит статус заказа в `ready_for_shipment`, что сразу отображается зеленым бейджем на Канбан-доске в веб-панели.

## 🛠 Управление проектом через Docker Compose

| Команда | Действие |
| :--- | :--- |
| `docker compose ps` | Посмотреть статус всех 4 контейнеров |
| `docker compose logs -f` | Логи всех сервисов в реальном времени |
| `docker compose logs -f bot` | Логи Telegram-бота |
| `docker compose restart backend` | Перезапустить бэкенд |
| `docker compose down` | Остановить стек с сохранением данных |
| `docker compose down -v` | Полный сброс (удаление базы данных и томов) |
